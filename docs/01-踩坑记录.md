# 踩坑记录 —— 这份文档比代码更值钱

> 下面每一条，都是真实踩过的坑。**代码可以抄，坑抄不走。**

---

## 1. 接口字段大小写不一致

```
/book/bookmarklist  →  bookId   （大写 D）
/review/list/mine   →  bookid   （小写 d）
```

**传错了不会报错，只会静默返回空。** 排查了很久才发现。

---

## 2. 想法会被截断

`/review/list/mine` 的 `count` **默认值很小**，必须显式传 **100**。

否则：**旧的想法会消失**，你以为自己没写过。

---

## 3. 返回顺序是乱的，不能直接用

`bookmarklist` 返回的是**划线时间倒序**，如果直接渲染笔记，读者会看到"跳来跳去"的句子。

正确做法（两层排序）：

```
① 章节之间：按 chapterinfo 的 chapterIdx 升序
   ⚠️ chapterUid 要统一成字符串再比较
② 章节内：按划线的 range 起始位置升序（还原文中先后）
```

**公众号文章没有目录** → 归入"全文"单章节。

---

## 4. 一条划线可能挂多条想法

**错误做法**：用 `range` 当 key 建字典 → **第二条想法被覆盖**。

**正确做法**：

- 想法靠 `review.abstract`（划线原文）+ `review.range`（位置）关联到划线
- **只有 range 和 content 完全一致时才去重**
- 想法里的多段换行**必须保留**

---

## 5. 一条想法只有一个 💭

**早期格式**：想法每换一行就加一个 `💭` → 视觉上像"多条想法"。

**用户要的格式**：

```
> 💭 第一段（只有首段带 💭）
第二段原样换行，不加任何前缀
```

---

## 6. 全量同步太慢 → 用书架 sort 做变化检测

`/user/notebooks` 返回每本书的 `sort` 字段（会随划线/想法变化）。

**做法**：把它存成快照，**只同步 sort 变了的书**。

---

## 7. ima 笔记重建的锚点陷阱

`export_note_blocks` 返回的 `blocks[0]` 是**虚拟块** `_begin_`（不是内容块）。

**如果拿它当删除起点** → 会把原有内容全删，**而且因为去掉了标题行，笔记会丢标题**。

**正确做法**：

```
锚点用 _begin_ 并跳过它
→ 删除其余所有 editable 块
→ APPEND 完整 md（含标题行）
```

---

## 8. 引用块里的中文会被转义

在 ima 笔记里写 Markdown 引用块（`> `），**换行后如果行首是中文全角字符**，会被转成 HTML 数字实体：

```
> 我不需要...   →   > &#x6211;不需要...
```

客户端可能显示为乱码串。

**规避**：注脚/说明类内容**改用普通段落**，或把中文从行首挪开。

**校验**：导出 md 后检查 `'&#' in md` 是否为 `False`。

---

## 9. 知识库写入不可逆

ima 的知识库和笔记**没有删除 API**。

**所以**：写入前**必须先 `get_knowledge_list` 检查目标文件夹有没有同名条目**。

重复导入**只能**手动在客户端删，且要先重命名打标记。

---

## 10. 增量更新要区分"内容变"和"格式变"

格式修复（比如想法多段排版）触发的重建，**不该算作内容更新** ——
否则每次同步都会无谓地重建所有笔记。

---

## 附：验证永远要用底层接口

**Fetch 工具读笔记有缓存延迟** —— 验证内容准确性时，
要用 `export_note_blocks` / `export_note`，不要用 Fetch。
